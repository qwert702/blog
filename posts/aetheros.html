项目 · AetherOS

把内核之上的那一层，重写一遍

2026-11-01 · 8 分钟阅读 · 源码

AetherOS 是一个不太“正常”的操作系统项目：它不重写内核，而是把 Linux 内核之上的那一层——PID 1、窗口合成器、终端、中文输入法、AI 中枢——从零写了一遍。

为什么不是“再写一个内核”

重写内核很酷，但它不解决用户真正感知到的问题。Android 和 ChromeOS 都用 Linux 内核，产品差异却发生在用户态。把几年时间花在一个跑不了真实软件的半成品内核上，换来的可能只是“内核是自己写的”这句话。

所以这个项目把力气放在更稀缺的地方：让自研的桌面、终端、输入法和 AI 真的能装真实 Linux 软件，真的能从 ISO 启动，真的能被别人复跑验证。

现在有什么

  • 7 个 Rust crate，约 5.2 万行代码；
  • 自研 PID 1、fbdev 合成器、PTY/VT 终端、中文输入法、安装器与应用包格式；
  • L0–L3 权限闸门、确认令牌、审计日志；
  • QEMU / VirtualBox / VMware 启动验证，以及 57 档逐像素回归；
  • 约 41 MB 的可引导 ISO。

这些数字不是用来堆简历的。它们背后是一个更重要的判断：“能跑”与“可验证”之间，隔着一整套测试、门禁和诚实的边界说明。

还没做到什么

物理机、真 GPU、真外设还没有系统验收；Wayland/DRM 仍是一个待决策的方向；已发布的 v0.1.1 ISO 还存在装机限制，需要重建产物。项目文档里把这些写成“未验证”，而不是“应该可以”。

一个标了已完成但没验证的项，比一个明确未完成的项更危险。

如果你对“从内核之上重写用户态”这件事感兴趣，可以从 GitHub 仓库和文档入口开始。欢迎 Issue、PR，也欢迎只是把它跑起来看看。
